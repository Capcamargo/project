# Deploy GiftMatch

## Платформа публикации

Render.com

## Публичная ссылка MVP

https://giftmatch-qqdu.onrender.com

## Что опубликовано

Опубликована веб-версия GiftMatch из папки `projects/giftmatch/`.

Ключевые страницы:

- `app.html` — главная страница и основной сценарий подбора;
- `register.html` — регистрация и вход;
- `verify-step.html` — подтверждение входа;
- `cabinet.html` — личный кабинет пользователя;
- `pricing.html` — выбор тарифа;
- `payment-success.html` — учебный тестовый платежный сценарий и подтверждение активации;
- `app.css` — основные стили;
- `app.js` — логика главной страницы.

## Backend и данные

Backend как отдельный сервер не используется. Данные и серверная логика вынесены в Supabase.

Используется:

- Supabase Auth — регистрация, вход и сессии;
- Supabase PostgreSQL — таблицы `profiles`, `gift_presets`, `gift_requests`, `gift_recommendations`;
- Supabase RLS — разделение пользовательских данных;
- Supabase Edge Functions — рекомендации, данные аккаунта, сохранение подборок.

## Supabase-проект

Название проекта: `GiftMatch`  
Регион: `eu-north-1`  
Основная база: PostgreSQL 17

## Что проверить после деплоя

1. Главная страница открывается по публичной ссылке.
2. CTA «Начать подбор» прокручивает к форме.
3. Каталог пресетов отображается.
4. Кнопка «Взять за основу» заполняет форму.
5. Форма подбора возвращает рекомендации.
6. Регистрация и вход работают.
7. Кабинет показывает профиль пользователя.
8. Сохраненная подборка появляется в кабинете.
9. Free-лимит открывает paywall.
10. Страница тарифов открывается.
11. Тестовый платежный сценарий обновляет тариф.
12. После активации пользователь возвращается в кабинет.

## Переменные и ключи

Публичный frontend использует Supabase URL и publishable key. Секретные ключи service role не должны храниться во frontend-файлах.

## Ограничения текущего deploy

- Платежный сценарий учебный и демонстрационный.
- Реальная интеграция с платежным провайдером не подключена.
- При production-развитии нужно добавить webhook платежной системы и серверную проверку оплаты.
- Желательно добавить отдельную админ-панель и rate limit для Edge Functions.

## Как объяснять деплой на экзамене

GiftMatch опубликован как статический frontend на Render. Для backend-части используется Supabase: база данных, авторизация, RLS и Edge Functions. Такой подход подходит для MVP, потому что позволяет быстро выпустить работающий продукт без отдельной серверной инфраструктуры.
