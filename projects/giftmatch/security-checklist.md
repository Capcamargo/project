# Security checklist GiftMatch

## Цель

Показать, что даже учебный MVP учитывает базовые риски: приватность пользовательских данных, корректную работу авторизации, ограничение бесплатного плана и безопасное разделение публичных и приватных данных.

## 1. Auth

- Пользователь входит через Supabase Auth.
- Сессия сохраняется между страницами.
- Личный кабинет доступен только после входа.
- Сохранение подборок требует авторизации.
- После выхода профиль и сохранения очищаются из текущего интерфейса.

## 2. Приватные данные

Приватными считаются:

- профиль пользователя;
- запросы на подбор подарков;
- рекомендации пользователя;
- сохраненные подборки;
- тарифный статус профиля.

Эти данные не должны быть доступны другим пользователям.

## 3. RLS

### `profiles`

Пользователь читает и обновляет только свой профиль.

### `gift_requests`

Пользователь читает, создает, обновляет и удаляет только свои запросы.

### `gift_recommendations`

Пользователь читает, создает, обновляет и удаляет только свои рекомендации.

### `gift_presets`

Публичное чтение разрешено. Публичная запись не используется.

## 4. Edge Functions

В Supabase активны Edge Functions:

- `giftmatch-recommendations`;
- `giftmatch-account`;
- `giftmatch-save-selection`.

Для них включен `verify_jwt = true`, поэтому функции ожидают авторизованный запрос.

## 5. Paywall

- На Free-плане действует лимит сохранений.
- После достижения лимита пользователь видит тарифный сценарий.
- Paywall появляется после того, как пользователь уже получил ценность от сервиса.
- Текущий платежный сценарий является учебной имитацией.

## 6. Платежный сценарий

Для курса реализован тестовый сценарий оплаты. Он нужен, чтобы показать продуктовую логику:

1. пользователь выбирает тариф;
2. переходит на отдельный платежный шаг;
3. подтверждает тестовый сценарий;
4. профиль получает обновленный план.

Для реального production-продукта нужно заменить этот сценарий на платежного провайдера и server-side webhook.

## 7. Что уже сделано

- RLS включен для пользовательских таблиц.
- Публичные пресеты отделены от приватных данных.
- Supabase security advisor не показывает активных security warnings.
- RLS-политики оптимизированы через `(select auth.uid())`.
- Секретные service-role ключи не должны находиться во frontend-коде.

## 8. Что желательно добавить после MVP

- Rate limit для функции рекомендаций.
- Блокировку кнопки отправки формы на время запроса.
- Серверную обработку настоящей оплаты.
- Админ-роль для управления пресетами.
- Журнал ключевых событий: регистрация, подбор, сохранение, paywall, тестовая активация.

## 9. Проверочный сценарий

1. Открыть сайт как гость.
2. Проверить, что публичные пресеты видны.
3. Попробовать сохранить подборку без входа.
4. Убедиться, что сервис просит войти.
5. Войти в аккаунт.
6. Сохранить подборку.
7. Открыть кабинет и увидеть только свои данные.
8. Проверить, что после лимита Free появляется тарифный сценарий.
9. Пройти тестовую активацию тарифа.
10. Вернуться в кабинет и проверить обновленный план.
