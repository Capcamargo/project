# Аналитика GiftMatch

## Зачем нужна аналитика

Аналитика нужна, чтобы проверять поведение пользователей не по ощущениям, а по фактам:

- куда пользователи нажимают;
- доходят ли они до формы;
- где бросают сценарий;
- работает ли CTA;
- появляется ли интерес к тарифам;
- понятен ли paywall.

## Рекомендуемый инструмент

Microsoft Clarity.

Причины выбора:

- быстро подключается через script в `<head>`;
- показывает heatmaps;
- показывает session recordings;
- подходит для учебного MVP;
- не требует сложной backend-интеграции.

## Какие страницы нужно покрыть

- `app.html` — главная страница, каталог, форма, результаты;
- `register.html` — регистрация и вход;
- `cabinet.html` — личный кабинет;
- `pricing.html` — выбор тарифа;
- `payment-success.html` — учебный платежный сценарий и подтверждение.

## События, которые важно отслеживать

### Главная страница

- клик по «Начать подбор»;
- клик по «Посмотреть примеры»;
- клик по «Взять за основу» в каталоге;
- скролл до формы подбора.

### Форма подбора

- начало заполнения формы;
- отправка формы;
- успешное получение рекомендаций;
- ошибка получения рекомендаций.

### Сохранение

- клик по «Сохранить подборку»;
- переход к регистрации после попытки сохранения;
- успешное сохранение;
- достижение лимита Free.

### Paywall и тарифы

- открытие paywall;
- переход на страницу тарифов;
- выбор тарифа;
- переход к тестовому платежному шагу;
- завершение тестовой активации.

## Что показать на экзамене

1. Скриншот Dashboard в Microsoft Clarity.
2. Heatmap главной страницы.
3. 1–2 записи пользовательских сессий.
4. Краткий вывод: где пользователи кликают и доходят ли до формы.

## Что считать успехом MVP

- Пользователь доходит от главного экрана до формы.
- Пользователь отправляет форму и видит рекомендации.
- Пользователь понимает, зачем нужен аккаунт.
- Пользователь пытается сохранить подборку.
- Пользователь видит тарифный шаг после Free-лимита.

## Что улучшать по данным аналитики

- Если мало кликов по CTA — усилить первый экран.
- Если пользователи бросают форму — сократить количество полей.
- Если не сохраняют подборки — лучше объяснить ценность кабинета.
- Если не переходят к тарифам — сделать paywall понятнее.
- Если не завершают тестовый платежный сценарий — упростить страницу оплаты.
