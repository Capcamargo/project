# RLS notes

GiftMatch хранит профили пользователей, запросы на подбор подарков, результаты рекомендаций и публичные пресеты. Для учебного MVP важно показать, что пользовательские данные разделены на уровне базы данных, а не только на уровне интерфейса.

## Общий принцип

- Гость может читать только публичные пресеты подарков.
- Авторизованный пользователь работает только со своими профилями, запросами и рекомендациями.
- Edge Functions вызываются с JWT и выполняют операции в контексте активного пользователя.

## Таблица `profiles`

Назначение: профиль пользователя, email, имя, тариф и статус платного доступа.

Политики:

- `select`: пользователь читает только строку своего профиля;
- `insert`: пользователь создает только собственный профиль;
- `update`: пользователь обновляет только собственный профиль.

## Таблица `gift_presets`

Назначение: публичный каталог готовых идей подарков.

Политики:

- `select`: доступен гостям и авторизованным пользователям;
- публичная запись не предусмотрена.

Эта таблица не содержит персональных пользовательских данных, поэтому публичное чтение допустимо для MVP.

## Таблица `gift_requests`

Назначение: пользовательские запросы на подбор подарка.

Политики:

- `select`: пользователь читает только свои запросы;
- `insert`: пользователь создает запрос только для своего аккаунта;
- `update`: пользователь обновляет только свои запросы;
- `delete`: пользователь удаляет только свои запросы.

## Таблица `gift_recommendations`

Назначение: результаты рекомендаций, связанные с пользователем и конкретным запросом.

Политики:

- `select`: пользователь читает только свои рекомендации;
- `insert`: пользователь создает рекомендации только для своего аккаунта;
- `update`: пользователь обновляет только свои рекомендации, например статус сохранения;
- `delete`: пользователь удаляет только свои рекомендации.

## Performance-fix для RLS

В живой базе политики используют форму:

```sql
user_id = (select auth.uid())
```

и:

```sql
id = (select auth.uid())
```

Так Supabase не переоценивает `auth.uid()` для каждой строки в больших выборках.

## Что проверить перед демонстрацией

1. Гость видит публичные пресеты.
2. Гость не получает приватные пользовательские записи.
3. Авторизованный пользователь видит свой профиль.
4. Авторизованный пользователь видит свои запросы и рекомендации.
5. Сохраненные рекомендации появляются в кабинете того же пользователя.
6. Free-лимит открывает тарифный сценарий.
7. Тестовая активация тарифа обновляет поле `plan` в профиле.

## Ограничения учебного MVP

- Платежный сценарий является демонстрационным.
- Для реального продукта платежную активацию нужно переносить на серверную сторону и связывать с платежным провайдером.
- Для дальнейшего развития полезно добавить ограничение частоты запросов к Edge Function рекомендаций.
