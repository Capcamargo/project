# Supabase

Материалы для локальной и облачной базы данных GiftMatch.

## Структура

- `config.toml` — локальная конфигурация Supabase CLI;
- `migrations/` — миграции проекта;
- `functions/` — исходники Edge Functions, которые развернуты в Supabase;
- `seed.sql` — стартовые данные для пресетов GiftMatch;
- `schema.sql` — актуальная плоская версия схемы для ручного запуска в SQL Editor;
- `queries.md` — список ключевых запросов и сценариев;
- `rls-notes.md` — заметки по ограничениям доступа;
- `sample-data.sql` — пример тестовых записей.

## Как использовать локально

1. Открыть папку `projects/giftmatch/supabase/`.
2. Запустить Supabase CLI в режиме local development.
3. Применить миграции из `migrations/`.
4. Загрузить стартовые данные из `seed.sql`.
5. После этого подключать frontend к локальной или облачной базе.

## Как использовать без локального Supabase

1. Открыть Supabase Studio или SQL Editor в облачном проекте.
2. Выполнить SQL из `schema.sql`.
3. При необходимости отдельно выполнить вставки из `seed.sql`.
4. Проверить RLS-политики и Edge Functions в Supabase Dashboard.

## Что покрывает схема

- профили пользователей;
- тарифы и статус тестовой активации;
- роли `user` и `admin`;
- запросы на подбор подарка;
- результаты рекомендаций;
- сохраненные подборки;
- публичные пресеты для быстрого старта;
- RLS для пользовательских данных;
- admin read policies для учебной админ-панели.

## Таблицы

### `profiles`

Хранит профиль пользователя: email, имя, план, статус платного доступа и роль.

### `gift_presets`

Публичный каталог пресетов подарков. Его можно читать без входа.

### `gift_requests`

Запросы пользователей на подбор подарков.

### `gift_recommendations`

Рекомендации, связанные с пользователем и конкретным запросом. Поле `is_saved` отвечает за отображение в кабинете.

## Edge Functions

В Supabase используются функции:

- `giftmatch-recommendations` — создает запрос и рекомендации, включает rate limit 10 запросов за 10 минут;
- `giftmatch-account` — загружает данные аккаунта;
- `giftmatch-save-selection` — сохраняет выбранные рекомендации.

Для функций включен `verify_jwt = true`.

## Admin-доступ

Для демонстрации ролей добавлен файл `admin.html`. Чтобы открыть админ-панель, нужно назначить тестовому профилю роль:

```sql
update public.profiles
set role = 'admin'
where email = 'admin@example.com';
```

Обычный пользователь с `role = 'user'` не получает доступ к admin-dashboard.

## RLS

RLS включен для всех пользовательских таблиц. Политики используют форму `(select auth.uid())`, чтобы избежать лишней переоценки `auth.uid()` на каждую строку.

## Проверка перед демонстрацией

- пресеты читаются на главной странице;
- регистрация создает профиль;
- форма создает `gift_requests`;
- Edge Function создает `gift_recommendations`;
- сохранение отмечает рекомендации как `is_saved = true`;
- кабинет показывает только данные текущего пользователя;
- Free-лимит открывает paywall;
- тестовая активация тарифа обновляет `profiles.plan`;
- `admin.html` открывается только для профиля с `role = 'admin'`.
