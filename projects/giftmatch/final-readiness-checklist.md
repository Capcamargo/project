# Final readiness checklist GiftMatch

Этот чеклист нужен для последней проверки перед сдачей и демонстрацией MVP.

## 1. Публичная ссылка

Открыть:

https://giftmatch-qqdu.onrender.com

Проверить:

- главная страница загружается;
- стили подключены;
- изображения каталога отображаются;
- кнопки в шапке работают;
- нет критических ошибок в консоли браузера.

## 2. Основной пользовательский сценарий

Проверить маршрут:

1. Открыть главную страницу.
2. Нажать «Начать подбор».
3. Заполнить форму.
4. Получить рекомендации.
5. Попробовать сохранить подборку.
6. Войти или зарегистрироваться.
7. Сохранить подборку.
8. Открыть кабинет.
9. Увидеть сохраненную рекомендацию.

## 3. Free-limit и тарифный сценарий

Проверить:

1. Пользователь на Free-плане может сохранить первые подборки.
2. При достижении лимита появляется paywall.
3. Страница `pricing.html` открывается.
4. Выбор тарифа переводит к тестовой активации.
5. `payment-success.html` явно показывает, что это учебная тестовая активация.
6. Реальные данные карты не запрашиваются.
7. После подтверждения тариф отображается в кабинете.

## 4. Admin-role

Проверить обычным пользователем:

- открыть `admin.html`;
- увидеть сообщение об отсутствии admin-роли.

Проверить администратором:

1. Назначить роль:

```sql
update public.profiles
set role = 'admin'
where email = 'admin@example.com';
```

2. Войти под этим email.
3. Открыть `admin.html`.
4. Проверить, что видны показатели:
   - пользователи;
   - запросы;
   - рекомендации;
   - сохранения;
   - пресеты.

## 5. Supabase

Проверить в Supabase Dashboard:

- таблица `profiles` содержит тестового пользователя;
- таблица `gift_presets` заполнена;
- таблица `gift_requests` пополняется после формы;
- таблица `gift_recommendations` пополняется после подбора;
- сохранение ставит `is_saved = true`;
- RLS включен;
- Edge Functions активны;
- `verify_jwt = true` для функций.

## 6. Supabase Advisor

Проверить:

- Security Advisor — без критических предупреждений;
- Performance Advisor — без `multiple permissive policies` warnings;
- возможный `unused_index` info-level пункт допустим для новой базы.

## 7. Hardening

Проверить:

- быстрый повторный клик по «Показать идеи» блокируется;
- быстрый повторный клик по «Сохранить подборку» блокируется;
- при частых запросах Edge Function возвращает rate limit;
- пользователь видит понятное сообщение, а не техническую ошибку.

## 10. Короткий текст для объяснения проекта

GiftMatch — это MVP сервиса персонализированного подбора подарков. Пользователь указывает повод, бюджет и интересы получателя, получает объяснимые рекомендации, сохраняет подходящие варианты в кабинете и при достижении лимита Free видит тарифный сценарий. Проект опубликован на Render, использует Supabase Auth, PostgreSQL, RLS и Edge Functions. Платежный сценарий реализован как учебная тестовая активация, а не настоящая платежная интеграция.

## 11. Что честно назвать ограничениями MVP

- реальная платежная интеграция не подключена;
- LLM-генерация подарков не используется, рекомендации строятся на пресетах и правилах;
- admin-панель минимальная и нужна для учебной демонстрации ролей;
- Microsoft Clarity нужно подключить после создания реального Clarity Project ID;
- для production потребуется webhook оплаты, расширенная аналитика и более строгий rate limit.
