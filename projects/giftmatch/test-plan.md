# Test plan GiftMatch

## Цель

Проверить, что опубликованный MVP проходит основной пользовательский путь и корректно работает с Supabase, авторизацией, сохранениями, paywall, тестовой активацией тарифа, admin-ролью и базовой защитой от повторных действий.

## 1. Гость

### Шаги

1. Открыть https://giftmatch-qqdu.onrender.com.
2. Нажать «Начать подбор».
3. Заполнить форму или выбрать готовый пример из каталога.
4. Получить рекомендации.
5. Нажать «Сохранить подборку».

### Ожидаемый результат

- Главная страница открывается.
- Форма работает.
- Рекомендации отображаются.
- При попытке сохранить подборку сервис предлагает войти или зарегистрироваться.

## 2. Новый пользователь

### Шаги

1. Открыть регистрацию.
2. Ввести email и имя.
3. Подтвердить вход по сценарию Supabase Auth.
4. Вернуться к GiftMatch.
5. Создать подборку.
6. Сохранить подборку.
7. Открыть кабинет.

### Ожидаемый результат

- Пользователь входит в аккаунт.
- В `profiles` появляется профиль.
- Подборка сохраняется.
- В кабинете видны профиль и сохраненные рекомендации.

## 3. Сценарий подбора

### Шаги

1. Ввести повод: День рождения.
2. Ввести бюджет: до 5000 ₽.
3. Ввести отношение: Друг.
4. Ввести интересы: настольные игры, кофе, путешествия.
5. Добавить заметку: нужен небанальный и полезный подарок.
6. Отправить форму.

### Ожидаемый результат

- Создается запись в `gift_requests`.
- Создаются записи в `gift_recommendations`.
- Пользователь видит несколько карточек с объяснениями.
- У карточек есть название, причина, бюджет, категория и показатель уместности.

## 4. Frontend hardening

### Шаги

1. Заполнить форму подбора.
2. Быстро нажать «Показать идеи» несколько раз подряд.
3. После появления рекомендаций быстро нажать «Сохранить подборку» несколько раз подряд.

### Ожидаемый результат

- Кнопка отправки формы временно блокируется.
- Повторное нажатие показывает сообщение: «Подборка уже собирается. Подождите несколько секунд.»
- Кнопка сохранения временно блокируется.
- Повторное сохранение показывает сообщение: «Сохранение уже выполняется. Подождите несколько секунд.»
- В базе не появляется лишняя серия дублей от быстрых повторных кликов.

## 5. Server-side rate limit

### Шаги

1. Войти в аккаунт.
2. Сделать много запросов подбора подряд.
3. Достичь лимита Edge Function.

### Ожидаемый результат

- Функция `giftmatch-recommendations` ограничивает частоту запросов.
- Лимит MVP: 10 подборок за 10 минут на пользователя.
- При превышении лимита пользователь получает понятное сообщение о необходимости подождать.

## 6. Кабинет

### Шаги

1. Войти в аккаунт.
2. Открыть `cabinet.html`.
3. Проверить профиль.
4. Проверить сохраненные рекомендации.

### Ожидаемый результат

- Отображается email пользователя.
- Отображается текущий тариф.
- Сохраненные подборки видны только этому пользователю.

## 7. Free-limit

### Шаги

1. Войти пользователем на Free-плане.
2. Сохранить первую подборку.
3. Сохранить вторую подборку.
4. Попробовать сохранить третью подборку.

### Ожидаемый результат

- Первые две подборки сохраняются.
- На третьей попытке появляется paywall.
- Пользователь получает понятный переход к тарифам.

## 8. Тарифный сценарий

### Шаги

1. Открыть `pricing.html`.
2. Выбрать Plus.
3. Перейти к тестовому шагу активации.
4. Проверить предупреждение о том, что это учебный сценарий.
5. Ввести email и имя.
6. Подтвердить тестовую активацию.
7. Вернуться в кабинет.

### Ожидаемый результат

- Выбранный тариф отображается на странице активации.
- Пользователь видит предупреждение, что реальные данные карты вводить не нужно.
- После подтверждения профиль получает обновленный `plan`.
- В кабинете отображается новый тариф.

## 9. Проверка RLS

### Шаги

1. Войти пользователем A.
2. Создать и сохранить подборку.
3. Войти пользователем B.
4. Открыть кабинет.

### Ожидаемый результат

- Пользователь B не видит сохранения пользователя A.
- Пользователь B видит только свои данные.
- SELECT-политики в Supabase объединяют доступ владельца и admin-доступ без `multiple permissive policies` warnings.

## 10. Admin-role

### Шаги

1. Создать или выбрать тестовый профиль.
2. Назначить роль администратора через SQL Editor:

```sql
update public.profiles
set role = 'admin'
where email = 'admin@example.com';
```

3. Войти под этим профилем.
4. Открыть `admin.html`.
5. Открыть `admin.html` обычным пользователем.

### Ожидаемый результат

- Admin видит агрегированные показатели MVP.
- Обычный пользователь видит сообщение об отсутствии admin-роли.
- Доступ контролируется через Supabase RLS.

## 11. Проверка публикации

### Шаги

1. Открыть сайт по Render-ссылке.
2. Проверить главную страницу.
3. Проверить форму.
4. Проверить регистрацию.
5. Проверить кабинет.
6. Проверить тарифы.
7. Проверить `admin.html`.

### Ожидаемый результат

- Все основные страницы открываются по публичной ссылке.
- CSS и JS загружаются.
- Supabase-запросы выполняются.
- Нет критических ошибок в пользовательском сценарии.

## 12. Проверка fallback

### Шаги

1. Временно смоделировать ошибку получения рекомендаций.
2. Отправить форму.

### Ожидаемый результат

- Пользователь все равно видит локальные fallback-рекомендации.
- Интерфейс не ломается.
- При последующем входе сервис пытается восстановить подборку через Supabase.

## 13. Supabase Advisor

### Шаги

1. Открыть Supabase Advisor.
2. Проверить Performance.
3. Проверить Security.

### Ожидаемый результат

- Нет критических security warnings.
- Нет `multiple permissive policies` warnings.
- Возможный `unused_index` info-level пункт допустим для новой или малонаполненной базы.
